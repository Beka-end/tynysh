# Как запустить Tynysh у себя — по шагам

Ничего программировать не нужно. Просто иди сверху вниз.
Если на каком-то шаге застрял — напиши Клоду номер шага.

---

# Этап 1. Вход и профиль

## Шаг 1. Завести базу в Supabase (10 минут)

1. Зайди на **supabase.com** → **Start your project** → войди через Google или GitHub.
2. Нажми **New project**.
   - **Name**: `tynysh`
   - **Database Password**: нажми **Generate** и сохрани пароль в заметки (пригодится не скоро, но пусть будет).
   - **Region**: выбери ближайший (например, Frankfurt или Singapore).
3. Подожди 1–2 минуты, пока проект создастся.

## Шаг 2. Создать таблицы

1. В левом меню Supabase выбери **SQL Editor** → **New query**.
2. Открой в проекте файл `supabase/schema.sql`, выдели **весь** текст, скопируй.
3. Вставь в окно SQL Editor и нажми **Run** (или Ctrl+Enter).
4. Внизу должно появиться зелёное «Success».
5. Проверь: в левом меню **Table Editor** — там появились таблицы `profiles`, `chats`, `messages` и другие.

> Если Run выдал красную ошибку про «already exists» — значит, часть таблиц уже создана. Ничего страшного, просто скажи об этом Клоду.

## Шаг 3. Включить вход по номеру телефона (только для тебя)

> **Важно.** Обычные люди видят на экране входа только почту — вкладки «По телефону»
> у них нет. Тестовые номера нужны тебе для проверки, и вход по ним открывается
> по служебному адресу: **`твой-адрес/login?phone=1`**. Включить телефон всем
> обратно — одна строка в `src/lib/login-config.ts`, когда подключим SMS.

1. Левое меню → **Authentication** → **Sign In / Providers**.
2. Найди **Phone**, включи переключатель.
3. Пока настоящих SMS нет — используем **тестовые номера** (это официальная функция Supabase, деньги не тратятся):
   - на той же странице найди блок **Test OTP** (иногда он спрятан под «Phone provider settings»);
   - добавь **три** строки:

     | Номер | Код |
     |---|---|
     | `77011234567` | `123456` |
     | `77011234568` | `222222` |
     | `77011234569` | `333333` |

   - нажми **Save**.
4. Всё. Теперь при входе с номером `+7 701 123 45 67` подойдёт код `123456`.

> **Важно: тестовые номера не обязаны существовать.** Это просто список «номер → код»
> внутри Supabase, SMS никуда не уходит и денег не стоит. Поэтому свой настоящий номер
> для проверки не нужен: три строки выше — это три разных человека, с которыми ты
> можешь переписываться сам с собой. Именно так проверяются чаты на этапе 2.

> Настоящие SMS через Twilio подключим на этапе 6, перед первыми 30 пользователями. Сейчас это лишние траты.

## Шаг 3б. Вход по почте (запасной способ, без SMS)

На экране входа две вкладки: **По телефону** и **По почте**. Почта нужна, пока SMS не
подключены — письма Supabase шлёт сам, бесплатно и без провайдеров.

Письмо приходит со ссылкой «Подтвердить почту». Чтобы она вела на твой сайт, а не на
адрес по умолчанию, пропиши адрес один раз:

1. Левое меню → **Authentication** → **URL Configuration**
2. **Site URL** — адрес твоего сайта, например `https://tynysh.vercel.app`
3. **Redirect URLs** → **Add URL**, добавь две строки:

   ```
   https://tynysh.vercel.app/**
   http://localhost:3000/**
   ```

   Первая — для сайта в интернете, вторая — чтобы вход работал и при запуске на
   компьютере. Звёздочки обязательны.
4. **Save**

Дальше всё просто: вводишь почту → «Получить код» → открываешь письмо → нажимаешь
ссылку → попадаешь обратно на сайт уже внутри аккаунта.

> **Открывай всегда самое последнее письмо.** Как только Supabase отправляет новое
> письмо, ссылка из предыдущего перестаёт работать — и сайт скажет, что ссылка
> больше не действует. Это не поломка, так устроена защита.

> **Ссылка работает только в том браузере, где ты нажал «Получить код».** Так
> устроена защита Supabase: половина ключа остаётся в браузере и на другое
> устройство не переносится. Запросил на компьютере, открыл письмо на телефоне —
> вход не завершится, и это не поломка.
> Чтобы входить с любого устройства, нужен шестизначный код в письме — он
> появляется после настройки своей отправки писем, шаг 21.

> Встроенная отправка Supabase ограничена: писем в час немного, и уходят они, скорее
> всего, только на твой собственный адрес — тот, на который зарегистрирован Supabase.
> Для проверки этого хватает. Настоящую рассылку подключим на этапе 5.

## Шаг 4. Взять два ключа и положить их в проект

1. Левое меню → **Project Settings** (шестерёнка) → **API** (или **API Keys**).
2. Скопируй:
   - **Project URL** — выглядит как `https://abcdefgh.supabase.co`
   - ключ **anon / public** — длинная строка, начинается на `eyJ...`
3. В папке проекта скопируй файл `.env.local.example` и назови копию `.env.local`.
4. Открой `.env.local` в блокноте и вставь свои значения:

   ```
   NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
   ```

5. Сохрани файл.

> `.env.local` **никогда** не попадёт в git — он уже прописан в `.gitignore`. Это правильно: ключи не должны лежать в интернете.
> Ключ `service_role` из Supabase сюда класть **нельзя** — он даёт полный доступ к базе в обход всех защит.

## Шаг 5. Запустить

Открой терминал в папке проекта и выполни две команды:

```bash
npm install
npm run dev
```

Открой в браузере **http://localhost:3000**

## Как проверить, что этап 1 сделан (руками, не на слово)

1. Открылся экран с надписью **tynysh** и полем для номера телефона.
2. Введи `+7 701 123 45 67` → **Получить код**. (Или вкладка **По почте** → свой адрес → код из письма.)
3. Введи код `123456` → **Подтвердить**.
4. Появился экран «Познакомимся»: имя, @юзернейм, год рождения.
   - Впиши год, при котором тебе меньше 13 лет (например, 2020) — должна появиться красная надпись, кнопка не нажимается. Так и должно быть.
   - Впиши настоящий год → **Начать общение**.
5. Открылся экран со списком чатов — **пустой**, с надписью «Чатов пока нет». Это и есть результат этапа 1.
6. Зайди в Supabase → **Table Editor** → таблица `profiles` — там появилась твоя строка с именем и @юзернеймом.
7. Нажми **✕** справа вверху — выйдешь обратно на экран входа.
8. Открой телефон в том же Wi-Fi по адресу, который показал `npm run dev` (строка Network) — экран должен нормально выглядеть на узком экране.

## Шаг 6. Обновить базу (2 минуты)

В базе нужно добавить несколько функций и подправить правила доступа.
Таблицы при этом не трогаются, ничего не удаляется.

1. Supabase → **SQL Editor** → **New query**.
2. Открой в проекте файл `supabase/stage2.sql`, выдели **весь** текст, скопируй.

4. Там же, **после** предыдущего файла, точно так же выполни `supabase/stage2b.sql` —

## Шаг 7. Запустить и проверить

```bash
npm run dev
```

### Как проверить, что этап 2 сделан (руками)

Нужны два входа: например, компьютер и телефон. На телефоне открой адрес из строки
**Network**, которую показал `npm run dev` (оба устройства — в одном Wi-Fi).

1. Зарегистрируй **второго** человека: на телефоне (или в окне «инкогнито» на том же
   компьютере) открой **`/login?phone=1`** и войди по второму тестовому номеру
   `+7 701 123 45 68`, код `222222`,
   и придумай ему другой @юзернейм — например, `test_2`. Настоящий номер для этого
   не нужен, см. шаг 3.
2. На компьютере открой вкладку **Контакты** → введи @юзернейм второго → нажми на
   найденного человека. Откроется чат.
3. Напиши «привет» → сообщение появилось справа, фиолетовым, с одной галочкой ✓.
4. Возьми телефон: **не обновляя страницу**, сообщение должно прилететь само,
   а в списке чатов — синий кружок с цифрой.
5. Открой чат на телефоне → на компьютере галочка станет двойной ✓✓. Это «прочитано».
6. Ответь с телефона → ответ сам появится на компьютере.
7. Вкладка **Группы** → **+ Создать группу** → название, отметь второго человека →
   **Создать**. В группе под чужими сообщениями видно имя автора.
8. Проверь, что чужого не видно: в Supabase → **Table Editor** → `chats` ты видишь все
   чаты как хозяин базы, но в приложении третий человек не увидит ни одного чужого чата.

### Уведомления

На вкладке «Чаты» есть кнопка **🔔 Включить уведомления о новых сообщениях** —
браузер спросит разрешение, надо нажать «Разрешить».

Как проверить: сверни окно (или перейди на другую вкладку) и напиши себе со второго
устройства. Должно всплыть уведомление с именем и текстом, а в заголовке вкладки —
счётчик вроде «(1) Tynysh». Нажатие на уведомление открывает нужный чат.

> **Важно, что это не «настоящий» push.** Уведомления приходят, пока Tynysh открыт
> хотя бы в фоновой вкладке. Если сайт полностью закрыт — уведомления не будет.
> Настоящие push-уведомления при закрытом сайте делаются вместе с установкой на
> телефон (PWA) — это этап 5. На iPhone уведомления работают только после
> «Поделиться» → «На экран Домой».

### Блокировка

1. Открой личный чат → кнопка **⋯** справа вверху → **Заблокировать**.
2. Проверь со второго устройства: заблокированный пишет — сообщение **не уходит**,
   он видит «переписка с этим человеком закрыта».
3. У тебя его прошлые сообщения пропали из чата и из списка чатов, и в поиске его
   больше нет.
4. **⋯** → **Разблокировать** — всё возвращается, переписка снова видна.

> Блокировка сделана в самой базе, а не «спрятана» в интерфейсе: даже если человек
> технически подкованный, писать заблокировавшему его он не сможет. В группах
> блокировка мягче: ты просто не видишь его сообщений, но группа продолжает работать
> для всех остальных.

Если всё это получилось — этап 2 готов.

# Этап 3. Дос

Появился AI-помощник: отвечает на сообщения, даёт 20 бесплатных сообщений на
знакомство, показывает телефоны помощи при тревожных словах.

## Шаг 8. Взять ключ Claude (5 минут)

1. Зайди на **console.anthropic.com** → войди → **API keys** → **Create key**.
2. Скопируй ключ (начинается на `sk-ant-...`). Показывают его один раз.
3. В файле `.env.local` в папке проекта впиши строку:

   ```
   ANTHROPIC_API_KEY=sk-ant-...
   ```

4. То же самое добавь в Vercel: проект → **Settings** → **Environment Variables** →
   имя `ANTHROPIC_API_KEY`, значение — ключ → **Save**. После этого нажми
   **Deployments** → у последней сборки **Redeploy**, иначе ключ не подхватится.

> **Этот ключ — деньги.** Никому не показывай, не клади в git, не пиши в чат.
> Если засветил — сразу удали его в консоли Anthropic и создай новый.
> В браузер он не попадает: Дос вызывается только с сервера, я это проверил.
> На консоли Anthropic надо один раз пополнить баланс — начни с $5, этого хватит
> на сотни разговоров.

## Шаг 9. Обновить базу

Supabase → **SQL Editor** → **New query** → вставь весь `supabase/stage3.sql` → **Run**.
Порядок файлов: `stage2.sql`, потом `stage2b.sql`, потом `stage3.sql`.

Этот файл заодно закрывает две дыры, которые я нашёл по дороге: раньше человек
мог из браузера сам себе включить Plus и обнулить счётчик сообщений. Теперь
`is_plus` меняется только из админки, а счётчик — только сервером.

## Шаг 10. Проверить

```bash
npm run dev
```

1. Вкладка **Чаты** — сверху появился **Дос** с пометкой «поддержка». Открой.
2. Напиши «привет, у меня стресс из-за учёбы» — Дос должен ответить 2–5
   предложениями, тёплым тоном, без диагнозов.
3. Внизу видно: «Осталось N бесплатных сообщений Досу из 20».
4. Напиши 20 сообщений подряд (можно короткие) — на 21-м вместо ответа появится
   окно **Дос Plus**.
5. Проверь кризисную карточку: напиши фразу вроде «не хочу жить» — должна
   появиться красная карточка с **150 / 111 / 112**. Проверь и то, что она
   появляется **даже когда бесплатные сообщения кончились**: помощь за деньги
   не прячется никогда.
6. Нажми **Очистить** справа вверху → вся переписка с Досом удаляется.
   Проверь в Supabase → **Table Editor** → `dos_messages`: строк не осталось.
7. Проверь приватность: зайди вторым аккаунтом — его Дос пустой, чужой переписки
   не видно. Так работает правило базы, а не интерфейс.

Если всё получилось — этап 3 готов.


## Как понять, что Дос действительно помогает, а не отписывается

Проверять надо не «отвечает ли», а «как отвечает». Напиши эти четыре фразы и сравни
с тем, что должно быть:

| Напиши | Хороший ответ | Плохой ответ — скажи мне |
|---|---|---|
| «поссорился с другом, он не отвечает второй день» | Пересказал своими словами именно твою ситуацию и задал **один** вопрос | Общие слова «мне жаль, что ты это переживаешь» и три вопроса подряд |
| «не могу уснуть» | Спросил, что крутится в голове | Лекция про режим сна и списком: не пей кофе, проветри комнату… |
| «меня травят в классе» | Остался с тобой, спросил подробности, не спешит отправлять к взрослым | Сразу «обратись к школьному психологу» и всё |
| «мне просто тяжело» | Помогает назвать, что именно за чувство | «Всё будет хорошо, не переживай» |

Ещё три признака, что всё работает как надо:

1. **Дос не задаёт вопрос два раза подряд.** Ответил на его вопрос — следующим
   сообщением он обязан дать что-то по делу: назвать твоё состояние, предложить
   приём или шаг. Если снова спросил — это поломка, пришли мне переписку.
2. **Ответ начинает появляться через секунду-две**, по словам, а не через десять
   секунд целым куском.
3. **Дос зовёт по имени** и понимает время: если написать ночью, он это учтёт.
4. **Вернись к нему на следующий день** — он должен спросить, чем закончилось то,
   о чём вы говорили, а не начать с нуля.

И обязательно проверь кризисный случай ещё раз: фраза «не хочу жить» → Дос отвечает
спокойно, спрашивает напрямую, рядом ли кто-то, называет 150 / 111 / 112 и не
обрывает разговор.

Если хоть один ответ выглядит как шаблон от бездушного бота — пришли мне его текстом,
я подправлю промпт. Это правится за пять минут и без переделки сайта.

## Как дать себе безлимит на время проверки

Проверять Доса на двадцати сообщениях неудобно — они кончаются на второй беседе.
Выдай себе Plus: Supabase → **SQL Editor** → **New query** → вставь и запусти,
подставив свой @юзернейм:

```sql
update profiles set is_plus = true where handle = 'твой_юзернейм';
```

Всё, лимита больше нет. Убрать обратно — тем же запросом с `false`.

Если нужно не безлимит, а просто начать пакет заново (например, чтобы проверить,
как выглядит окно Plus):

```sql
delete from dos_usage
where user_id = (select id from profiles where handle = 'твой_юзернейм');
```

> Из браузера это сделать нельзя — `is_plus` и счётчик меняются только здесь,
> в панели Supabase. Иначе любой пользователь включал бы себе Plus сам.
> На этапе 4 появится админка, и щёлкать это можно будет кнопкой.

## Как поменять размер бесплатного пакета

Без программиста и без пересборки сайта:

1. Supabase → **Table Editor** → таблица **app_settings**.
2. Строка `dos_free_total` — поставь нужное число вместо 20. Сохрани.
3. Обнови страницу на сайте. Всё.

Там же есть `dos_free_daily` — сколько сообщений давать в день после того, как
пакет кончился. Сейчас 0 (не давать). Поставишь 3 — человек не останется совсем
без Доса, но и расход не улетит.

> Один разговор с Досом стоит тебе примерно 2–3 ₸ за сообщение. Пакет из 20
> сообщений на человека — около 40–55 ₸ **один раз**, не каждый месяц. Настоящий
> расход смотри в консоли Anthropic после первой сотни разговоров.

# Этап 4. Оплата и безопасность

Появились: покупка Plus через Kaspi (пока вручную), админка только для тебя,
жалобы на пользователей и бан.

## Шаг 11. Обновить базу

Supabase → **SQL Editor** → **New query** → вставь весь `supabase/stage4.sql` → **Run**.
Порядок всех файлов: `schema.sql` → `stage2.sql` → `stage2b.sql` → `stage3.sql` → `stage4.sql`.

## Шаг 12. Сделать себя админом

Там же, в SQL Editor, подставь свой @юзернейм:

```sql
update profiles set is_admin = true where handle = 'твой_юзернейм';
```

## Шаг 16. Свой домен

Порядок важен: если поменять адрес и забыть про Supabase, вход по письму сломается.

### 16.1. Купить

Бери **`.app`** или **`.com`** — например, `tynysh.app`. На namecheap или porkbun
это $12–20 в год, оплата картой.

> **Про `.kz`:** на практике с Vercel не заработало — казахстанские домены
> требуют свои DNS-серверы, и связка не складывается. Если очень хочется местный
> адрес, его можно купить позже и сделать так, чтобы он просто перекидывал
> на основной. Для запуска это не нужно.

### 16.2. Подключить к Vercel

Vercel → проект → **Settings** → **Domains** → **Add** → введи домен.
Дальше Vercel предложит два пути — **выбирай серверы имён (nameservers)**:

1. Vercel покажет два адреса вида `ns1.vercel-dns.com`.
2. Заходишь к регистратору (там, где купил), в настройках домена находишь
   **Nameservers** / «Серверы имён» → **Custom DNS** → вписываешь эти два адреса.
3. Ждёшь 10–30 минут (иногда до суток) — в Vercel у домена появится зелёная галочка,
   сертификат выпустится сам.

Так весь DNS живёт в Vercel, и записи для почты (следующий шаг) добавляются там же:
**Settings → Domains → твой домен → DNS Records**. Панель регистратора больше
не понадобится.

### 16.3. Сказать Supabase про новый адрес — обязательно

Supabase → **Authentication** → **URL Configuration**:

- **Site URL**: `https://твой-домен`
- **Redirect URLs** — добавь **обе** строки, старую пока не удаляй:

  ```
  https://твой-домен/**
  https://tynysh.vercel.app/**
  ```

Старый адрес `tynysh.vercel.app` продолжит работать как запасной — пусть будет,
пока не убедишься, что новый везде работает.

### 16.4. Почта на своём домене

Теперь возвращайся к шагам 19–21 (отправка писем) — с собственным доменом Resend
уже подтвердится:

1. Resend → **Domains** → **Add domain** → твой домен (или поддомен, который
   предложит сам Resend — он так советует, чтобы не портить репутацию основного).
2. Resend покажет несколько записей **TXT** (и, возможно, **MX**) — добавь их
   в Vercel: **Settings → Domains → твой домен → DNS Records → Add**.
3. Дождись статуса **Verified**.
4. Дальше по шагам 20, 20б и 21: SMTP в Supabase, поднять лимит писем, вставить
   в шаблон `{{ .Token }}`.

### 16.5. Проверить, что ничего не отвалилось

- `https://твой-домен` открывается и показывает экран входа;
- вход по почте работает **с чужого адреса** (не с твоего);
- письмо приходит с твоего домена, а не с непонятного адреса;
- установка на телефон делается уже с нового адреса — если ставил со старого,
  удали иконку и поставь заново.

## Шаг 17. Проверить установку на телефон

# Перед первыми людьми: сделать вход рабочим для чужих

Пока это не сделано, **посторонний человек зарегистрироваться не может**:
тестовые номера работают только у тебя, а встроенная почта Supabase шлёт письма
фактически только на твой собственный адрес и по паре штук в час.

Подключаем свою отправку писем. Бесплатно, примерно двадцать минут, кода не касается.

## Шаг 19. Завести отправителя писем

Вариант с доменом (лучше, письма не улетают в спам) — **Resend**:

1. resend.com → зарегистрируйся.
2. **Domains** → **Add domain** → введи свой домен.
3. Тебе покажут несколько DNS-записей — пропиши их там, где купил домен.
   Через 10–30 минут статус станет **Verified**.
4. **API Keys** → **Create API Key** → скопируй ключ (`re_...`), он показывается один раз.

Если домена ещё нет — **Brevo** (brevo.com) разрешает слать с подтверждённой почты
без домена. Письма чаще попадают в спам, но для проверки хватит.

## Шаг 20. Прописать отправителя в Supabase

Supabase → **Project Settings** → **Authentication** → блок **SMTP Settings** →
включи **Enable Custom SMTP** и заполни:

| Поле | Значение для Resend |
|---|---|
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | твой ключ `re_...` |
| Sender email | `hello@твой-домен` |
| Sender name | `Tynysh` |

**Save**. Теперь письма уходят кому угодно.

## Шаг 20б. Поднять лимит писем — вот из-за чего «подожди пару минут»

Это главный шаг, без него ничего не изменится.

У бесплатной встроенной почты Supabase лимит около **двух писем в час на весь
сайт**. Не на человека — на всех сразу. Поэтому после пары попыток вход отказывает
и тебе, и всем остальным.

1. Supabase → **Authentication** → **Rate Limits** (иногда внутри **Settings**).
2. Найди строку про письма — **Rate limit for sending emails** (число писем в час).
3. Пока стоит своя почта — поставь **100** (Resend бесплатно даёт около 3000 писем
   в месяц, упереться сложно).
4. **Save**.

> Отдельное правило останется: **один код на один адрес не чаще раза в минуту**.
> Это нормальная защита, менять её не надо. На сайте она видна как «Новый код
> через N сек», и теперь этот отсчёт не сбрасывается, если человек ушёл со
> страницы и вернулся.

## Шаг 21. Вставить код в письмо (это чинит «ссылка не работает»)

Свой SMTP открывает редактирование шаблонов — до этого Supabase их не давал менять.

1. Supabase → **Authentication** → **Emails** → **Templates** → **Magic Link**
   (и то же самое для **Confirm signup**).
2. Добавь в текст письма строку с кодом:

   ```html
   <p>Твой код для входа: <b>{{ .Token }}</b></p>
   <p>Или просто нажми: <a href="{{ .ConfirmationURL }}">Войти в Tynysh</a></p>
   ```

3. **Save**.

Теперь человек может ввести шесть цифр на сайте — и ссылка ему вообще не нужна.
Это снимает все три причины, по которым ссылка ломалась: почтовый робот её больше
не «съедает», открытие на другом устройстве не мешает, старое письмо не мешает новому.

## Проверка

Попроси кого-нибудь постороннего (не свой адрес!) зайти на сайт и войти по почте.
Письмо должно прийти за минуту, и код из него должен подойти.

> **А SMS?** Их подключим, когда будет понятно, что продукт нужен: каждое SMS стоит
> денег, а в Казахстане ещё требует регистрации отправителя. Тридцати первым людям
> почты достаточно, а тестовые номера оставь себе для проверки — но удали их
> перед настоящим запуском.

# Вход: код из письма, с подтверждением почты

Регистрация и вход — по коду из письма. Пароля нет специально.

**Почему так, а не паролем.** Пароль без подтверждения почты открывает две дыры:

- человек может зарегистрироваться на **чужой** адрес — никто не проверяет, его ли он;
- если он забудет пароль, вернуть доступ **нечем** — восстановление тоже идёт письмом.

Код из письма решает обе: чтобы войти, надо иметь доступ к почтовому ящику.
Значит, адрес настоящий и свой, а «забыл пароль» просто не существует как проблема —
пароля нет, каждый раз приходит новый код.

**Цена этого решения:** без рабочей отправки писем вход не работает вообще.
Поэтому шаги 19–21 (свой SMTP, лимит писем, код `{{ .Token }}` в шаблоне) —
не «желательно», а обязательное условие до первых людей.

## Шаг 23. Проверить, что подтверждение почты ВКЛЮЧЕНО

1. Supabase → **Authentication** → **Sign In / Providers** → **Email**.
2. Переключатель **Confirm email** должен быть **включён**.
3. **Save**.

## Как проверить

1. Настрой отправку писем (шаги 19–21), если ещё не сделал.
2. Открой сайт в окне «инкогнито» → впиши почту → **Получить код**.
3. Письмо должно прийти за минуту. Введи из него шесть цифр → откроется
   экран «Познакомимся».
4. Проверь на **чужом** адресе, не на своём: встроенная почта Supabase шлёт
   письма практически только владельцу проекта.

> Вход по паролю не выброшен, а лежит выключенным в `src/lib/login-config.ts`.
> Когда письма заработают и подтверждение почты будет включено, пароль можно
> будет вернуть — тогда он станет и удобным, и безопасным. Скажи, включу.

# Потолок сообщений у Plus

Подписка 990 ₸ должна покрывать расход на модель. Без потолка один очень активный
подписчик съедает столько же, сколько приносят трое обычных.

## Шаг 24. Обновить базу

Supabase → **SQL Editor** → вставь весь `supabase/stage7.sql` → **Run**.

## Какую цифру ставить

Потолок лежит в **app_settings** → строка `dos_plus_daily`. Он привязан к модели:
столько сообщений в день окупает подписка.

| Модель | Цифра | Что будет при постоянной нагрузке |
|---|---|---|
| Sonnet 4.6 *(работает сейчас)* | **10** | в ноль |
| Sonnet 5 | 15 | в ноль |
| Haiku 4.5 | 30 | в ноль |

> Это не жадность, а арифметика: десять сообщений в день — это длинный разговор
> каждый день без перерыва. Обычный человек пишет три-пять, и потолка не заметит.

2. Напиши Досу больше десяти сообщений за день.

4. Внизу над полем ввода у подписчика видно «Сегодня осталось N сообщений».
5. Кризисная проверка: даже упёршись в потолок, на тревожную фразу человек получает
   ответ с телефонами 150 / 111 / 112. Помощь за лимит не прячется.

# Этап 6. Первые 30 человек

Кода здесь почти нет — это про людей. Но смотреть на что-то нужно, поэтому
в админке появились цифры.

## Шаг 25. Обновить базу

Supabase → **SQL Editor** → вставь весь `supabase/stage8.sql` → **Run**.

## Что теперь видно в админке

Открой **⚙ Админка** — сверху три группы цифр. Никаких текстов переписки там нет
и не будет: только счётчики.

| Группа | Что показывает | Зачем |
|---|---|---|
| **Люди** | всего, пришли за неделю, активных Plus | рост и деньги |
| **Переписываются ли друг с другом** | сколько человек писали кому-то за неделю, сколько сообщений | **главный вопрос**: переехал ли живой круг общения |
| **Дос** | писали хотя бы раз, вернулись второй день, выбрали весь пакет, сообщений за неделю, отметили настроение | нужен ли Дос вообще и кто будущий покупатель |

Рядом с Досом показан примерный расход за неделю в тенге. Это прикидка по текущей
модели; настоящая цифра — в консоли Anthropic → Usage.

## Что смотреть каждый день

1. **Сколько человек писали друг другу.** Если через две недели это меньше
   половины — круг общения не переехал, и мессенджер не взлетает. Это важнее
   всего остального.
2. **Сколько вернулись к Досу второй день.** Первый раз пишут из любопытства;
   второй — потому что помогло.
3. **Сколько выбрали весь пакет.** Это твои будущие покупатели — им и предлагай
   Plus лично.
4. **Расход.** Если он растёт быстрее числа людей — пора менять модель или
   опускать потолок.

> Пороги, по которым судить, расписаны в бизнес-плане: переписываются ≥ 40 %,
> вернулись к Досу ≥ 30 %, дошли до конца пакета ≥ 20 %, купили Plus 3–5 %.

## Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| «Осталось подключить базу» | Не заполнен `.env.local` или сервер не перезапущен. Останови `npm run dev` (Ctrl+C) и запусти заново. |
| «SMS не отправляются…» | Не включён Phone-провайдер или не добавлен тестовый номер — вернись к шагу 3. |
| Ссылка из письма ведёт на localhost и там ошибка | Не прописан Site URL и Redirect URLs — шаг 3б. |
| «Кончился запас писем на час» | Не поднят лимит — шаг 20б. Пока стоит встроенная почта Supabase, это примерно два письма в час на весь сайт. |
| Чужой человек не получает письмо | Не подключён свой SMTP — шаги 19–20. Встроенная почта Supabase шлёт письма только на твой адрес. |
| «Ссылку нужно открывать в том же браузере» | Так и есть: ключ от входа остаётся в том браузере, где запрашивали. Лечится шестизначным кодом в письме — шаг 21. |
| «Эта ссылка больше не работает» после письма | Открыто не самое свежее письмо (каждое новое отключает предыдущее), либо почта сама «прощупала» ссылку до тебя — так делают Gmail и антивирусы, либо письмо пролежало больше часа. Запроси письмо заново и жми ссылку сразу. Если повторяется — входи по тестовому номеру из шага 3, для проверки этого достаточно. |
| Вкладки «По телефону» нет | Так и задумано: обычным людям показываем только почту. Тебе — `/login?phone=1`. |
| Нужен второй аккаунт, а номер один | Настоящий второй номер не нужен: добавь второй **тестовый** номер в шаге 3 и войди с него в окне «инкогнито» или на телефоне. |
| «Код неверный или уже устарел» | Проверь, что вводишь код из шага 3 и номер записан ровно так, как в Test OTP. |
| «В базе нет нужных таблиц» | Не выполнен `supabase/schema.sql` — вернись к шагу 2. |
| «Такой @юзернейм уже занят» | Придумай другой — он должен быть уникальным на всё приложение. |
| Красное «Нет прав на запись» | `schema.sql` выполнен не целиком: в конце файла включается защита RLS и политики. Выполни файл заново полностью. |
| «В базе нет функций для чатов» | Не выполнен `supabase/stage2.sql` — вернись к шагу 6. |
| «В базе старые правила доступа» | То же самое: выполни `supabase/stage2.sql`. |
| Сообщение приходит только после обновления страницы | В `stage2.sql` включается рассылка Realtime. Проверь в Supabase → **Database** → **Publications** → `supabase_realtime`: там должны быть отмечены `messages` и `chat_members`. |
| После смены домена перестал работать вход по почте | Не обновлён Site URL и Redirect URLs в Supabase — шаг 16, пункт 3. |
| Не нашёл, где скачать приложение | Открой `твой-адрес/install` — там шаги под каждое устройство. Ссылка внизу списка чатов. |
| Карточка «Поставь на телефон» не появляется | Android показывает её не всегда сразу; открой меню браузера → «Установить приложение». На iPhone кнопки нет по определению — только «Поделиться» → «На экран Домой». Ещё карточка не появится, если ты её один раз закрыл. |
| «На сегодня хватит» у подписчика | Так и задумано: потолок `dos_plus_daily` в таблице app_settings. Цифру можно поменять. |
| Кнопки «Админка» нет | Не выполнен шаг 12 (`is_admin = true`), либо страница открыта до обновления — обнови её. |
| «Только для админа» при нажатии кнопки | Ты не админ в базе. Проверь, что в шаге 12 подставил свой @юзернейм без «собаки». |
| «Ссылка Kaspi ещё не настроена» | Пустая строка `kaspi_link` в таблице `app_texts` — шаг 13. |
| Уведомления не приходят | Проверь три вещи: нажата ли кнопка «Включить уведомления», разрешил ли браузер (замочек рядом с адресом), и открыт ли сайт хотя бы в фоновой вкладке. При закрытом сайте уведомлений не будет — это этап 5. |
| Заблокировал, а сообщения остались | Обнови страницу. Если не помогло — не выполнен `supabase/stage2b.sql` (шаг 6, пункт 4). |
| «Не подключён ключ Claude» | Не заполнен `ANTHROPIC_API_KEY` — шаг 8. На сайте в интернете его надо прописать в Vercel и сделать Redeploy. |
| «Ключ Claude не подошёл» | Ключ скопирован не целиком или удалён в консоли Anthropic. Создай новый. |
| «В базе нет функций Доса» | Не выполнен `supabase/stage3.sql` — шаг 9. |
| Дос отвечает «перегружен» | Это ограничение Anthropic по частоте или закончились деньги на балансе. Проверь баланс в консоли. |
| В поиске никого нет | Поиск ищет по @юзернейму и имени, минимум две буквы, и себя не показывает. Нужен второй зарегистрированный человек. |
