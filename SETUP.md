# Как запустить Tynysh у себя — по шагам

Ничего программировать не нужно. Просто иди сверху вниз.
Если на каком-то шаге застрял — напиши Клоду номер шага.

---

# Этап 1. Вход и профиль

## Шаг 1. Завести базу в Supabase (10 минут)

1. Зайди на **supabase.com** → **Start your project** → войди через Google или GitHub.
2. Нажми **New project**.
   - **Name**: `tynysh`
   - **Database Password**: нажми **Generate** и сохрани пароль в заметки (пригодится не скоро, но пусть будет).
   - **Region**: выбери ближайший (например, Frankfurt или Singapore).
3. Подожди 1–2 минуты, пока проект создастся.

## Шаг 2. Создать таблицы

1. В левом меню Supabase выбери **SQL Editor** → **New query**.
2. Открой в проекте файл `supabase/schema.sql`, выдели **весь** текст, скопируй.
3. Вставь в окно SQL Editor и нажми **Run** (или Ctrl+Enter).
4. Внизу должно появиться зелёное «Success».
5. Проверь: в левом меню **Table Editor** — там появились таблицы `profiles`, `chats`, `messages` и другие.

> Если Run выдал красную ошибку про «already exists» — значит, часть таблиц уже создана. Ничего страшного, просто скажи об этом Клоду.

## Шаг 3. Включить вход по номеру телефона

1. Левое меню → **Authentication** → **Sign In / Providers**.
2. Найди **Phone**, включи переключатель.
3. Пока настоящих SMS нет — используем **тестовые номера** (это официальная функция Supabase, деньги не тратятся):
   - на той же странице найди блок **Test OTP** (иногда он спрятан под «Phone provider settings»);
   - добавь **три** строки:

     | Номер | Код |
     |---|---|
     | `77011234567` | `123456` |
     | `77011234568` | `222222` |
     | `77011234569` | `333333` |

   - нажми **Save**.
4. Всё. Теперь при входе с номером `+7 701 123 45 67` подойдёт код `123456`.

> **Важно: тестовые номера не обязаны существовать.** Это просто список «номер → код»
> внутри Supabase, SMS никуда не уходит и денег не стоит. Поэтому свой настоящий номер
> для проверки не нужен: три строки выше — это три разных человека, с которыми ты
> можешь переписываться сам с собой. Именно так проверяются чаты на этапе 2.

> Настоящие SMS через Twilio подключим на этапе 6, перед первыми 30 пользователями. Сейчас это лишние траты.

## Шаг 3б. Вход по почте (запасной способ, без SMS)

На экране входа две вкладки: **По телефону** и **По почте**. Почта нужна, пока SMS не
подключены — письма Supabase шлёт сам, бесплатно и без провайдеров.

Письмо приходит со ссылкой «Подтвердить почту». Чтобы она вела на твой сайт, а не на
адрес по умолчанию, пропиши адрес один раз:

1. Левое меню → **Authentication** → **URL Configuration**
2. **Site URL** — адрес твоего сайта, например `https://tynysh.vercel.app`
3. **Redirect URLs** → **Add URL**, добавь две строки:

   ```
   https://tynysh.vercel.app/**
   http://localhost:3000/**
   ```

   Первая — для сайта в интернете, вторая — чтобы вход работал и при запуске на
   компьютере. Звёздочки обязательны.
4. **Save**

Дальше всё просто: вводишь почту → «Получить код» → открываешь письмо → нажимаешь
ссылку → попадаешь обратно на сайт уже внутри аккаунта.

> **Открывай всегда самое последнее письмо.** Как только Supabase отправляет новое
> письмо, ссылка из предыдущего перестаёт работать — и сайт скажет, что ссылка
> больше не действует. Это не поломка, так устроена защита.

> Шаблон письма редактировать не нужно — Supabase разрешает это только со своим SMTP.
> Ссылка работает с любого устройства: можно запросить вход на компьютере, а письмо
> открыть с телефона. Если в письме окажется ещё и шестизначный код, его можно ввести
> на сайте руками.

> Встроенная отправка Supabase ограничена: писем в час немного, и уходят они, скорее
> всего, только на твой собственный адрес — тот, на который зарегистрирован Supabase.
> Для проверки этого хватает. Настоящую рассылку подключим на этапе 5.

## Шаг 4. Взять два ключа и положить их в проект

1. Левое меню → **Project Settings** (шестерёнка) → **API** (или **API Keys**).
2. Скопируй:
   - **Project URL** — выглядит как `https://abcdefgh.supabase.co`
   - ключ **anon / public** — длинная строка, начинается на `eyJ...`
3. В папке проекта скопируй файл `.env.local.example` и назови копию `.env.local`.
4. Открой `.env.local` в блокноте и вставь свои значения:

   ```
   NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
   ```

5. Сохрани файл.

> `.env.local` **никогда** не попадёт в git — он уже прописан в `.gitignore`. Это правильно: ключи не должны лежать в интернете.
> Ключ `service_role` из Supabase сюда класть **нельзя** — он даёт полный доступ к базе в обход всех защит.

## Шаг 5. Запустить

Открой терминал в папке проекта и выполни две команды:

```bash
npm install
npm run dev
```

Открой в браузере **http://localhost:3000**

## Как проверить, что этап 1 сделан (руками, не на слово)

1. Открылся экран с надписью **tynysh** и полем для номера телефона.
2. Введи `+7 701 123 45 67` → **Получить код**. (Или вкладка **По почте** → свой адрес → код из письма.)
3. Введи код `123456` → **Подтвердить**.
4. Появился экран «Познакомимся»: имя, @юзернейм, год рождения.
   - Впиши год, при котором тебе меньше 13 лет (например, 2020) — должна появиться красная надпись, кнопка не нажимается. Так и должно быть.
   - Впиши настоящий год → **Начать общение**.
5. Открылся экран со списком чатов — **пустой**, с надписью «Чатов пока нет». Это и есть результат этапа 1.
6. Зайди в Supabase → **Table Editor** → таблица `profiles` — там появилась твоя строка с именем и @юзернеймом.
7. Нажми **✕** справа вверху — выйдешь обратно на экран входа.
8. Открой телефон в том же Wi-Fi по адресу, который показал `npm run dev` (строка Network) — экран должен нормально выглядеть на узком экране.

# Этап 2. Чаты

Появились: поиск людей по @юзернейму, личные чаты, группы, сообщения в реальном
времени и галочки «прочитано».

## Шаг 6. Обновить базу (2 минуты)

В базе нужно добавить несколько функций и подправить правила доступа.
Таблицы при этом не трогаются, ничего не удаляется.

1. Supabase → **SQL Editor** → **New query**.
2. Открой в проекте файл `supabase/stage2.sql`, выдели **весь** текст, скопируй.
3. Вставь в окно и нажми **Run**. Внизу должно появиться зелёное «Success».

> Этот файл можно запускать хоть десять раз подряд — ничего не сломается.
> Если ты только начинаешь с нуля, отдельного файла не нужно: в `supabase/schema.sql`
> всё это уже есть.

4. Там же, **после** предыдущего файла, точно так же выполни `supabase/stage2b.sql` —
   это блокировка людей. Порядок важен: сначала `stage2.sql`, потом `stage2b.sql`.

## Шаг 7. Запустить и проверить

```bash
npm run dev
```

### Как проверить, что этап 2 сделан (руками)

Нужны два входа: например, компьютер и телефон. На телефоне открой адрес из строки
**Network**, которую показал `npm run dev` (оба устройства — в одном Wi-Fi).

1. Зарегистрируй **второго** человека: на телефоне (или в окне «инкогнито» на том же
   компьютере) войди по второму тестовому номеру `+7 701 123 45 68`, код `222222`,
   и придумай ему другой @юзернейм — например, `test_2`. Настоящий номер для этого
   не нужен, см. шаг 3.
2. На компьютере открой вкладку **Контакты** → введи @юзернейм второго → нажми на
   найденного человека. Откроется чат.
3. Напиши «привет» → сообщение появилось справа, фиолетовым, с одной галочкой ✓.
4. Возьми телефон: **не обновляя страницу**, сообщение должно прилететь само,
   а в списке чатов — синий кружок с цифрой.
5. Открой чат на телефоне → на компьютере галочка станет двойной ✓✓. Это «прочитано».
6. Ответь с телефона → ответ сам появится на компьютере.
7. Вкладка **Группы** → **+ Создать группу** → название, отметь второго человека →
   **Создать**. В группе под чужими сообщениями видно имя автора.
8. Проверь, что чужого не видно: в Supabase → **Table Editor** → `chats` ты видишь все
   чаты как хозяин базы, но в приложении третий человек не увидит ни одного чужого чата.

### Уведомления

На вкладке «Чаты» есть кнопка **🔔 Включить уведомления о новых сообщениях** —
браузер спросит разрешение, надо нажать «Разрешить».

Как проверить: сверни окно (или перейди на другую вкладку) и напиши себе со второго
устройства. Должно всплыть уведомление с именем и текстом, а в заголовке вкладки —
счётчик вроде «(1) Tynysh». Нажатие на уведомление открывает нужный чат.

> **Важно, что это не «настоящий» push.** Уведомления приходят, пока Tynysh открыт
> хотя бы в фоновой вкладке. Если сайт полностью закрыт — уведомления не будет.
> Настоящие push-уведомления при закрытом сайте делаются вместе с установкой на
> телефон (PWA) — это этап 5. На iPhone уведомления работают только после
> «Поделиться» → «На экран Домой».

### Блокировка

1. Открой личный чат → кнопка **⋯** справа вверху → **Заблокировать**.
2. Проверь со второго устройства: заблокированный пишет — сообщение **не уходит**,
   он видит «переписка с этим человеком закрыта».
3. У тебя его прошлые сообщения пропали из чата и из списка чатов, и в поиске его
   больше нет.
4. **⋯** → **Разблокировать** — всё возвращается, переписка снова видна.

> Блокировка сделана в самой базе, а не «спрятана» в интерфейсе: даже если человек
> технически подкованный, писать заблокировавшему его он не сможет. В группах
> блокировка мягче: ты просто не видишь его сообщений, но группа продолжает работать
> для всех остальных.

Если всё это получилось — этап 2 готов.

## Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| «Осталось подключить базу» | Не заполнен `.env.local` или сервер не перезапущен. Останови `npm run dev` (Ctrl+C) и запусти заново. |
| «SMS не отправляются…» | Не включён Phone-провайдер или не добавлен тестовый номер — вернись к шагу 3. |
| Ссылка из письма ведёт на localhost и там ошибка | Не прописан Site URL и Redirect URLs — шаг 3б. |
| «Эта ссылка больше не работает» после письма | Открыто не самое свежее письмо (каждое новое отключает предыдущее), либо почта сама «прощупала» ссылку до тебя — так делают Gmail и антивирусы, либо письмо пролежало больше часа. Запроси письмо заново и жми ссылку сразу. Если повторяется — входи по тестовому номеру из шага 3, для проверки этого достаточно. |
| Нужен второй аккаунт, а номер один | Настоящий второй номер не нужен: добавь второй **тестовый** номер в шаге 3 и войди с него в окне «инкогнито» или на телефоне. |
| «Код неверный или уже устарел» | Проверь, что вводишь код из шага 3 и номер записан ровно так, как в Test OTP. |
| «В базе нет нужных таблиц» | Не выполнен `supabase/schema.sql` — вернись к шагу 2. |
| «Такой @юзернейм уже занят» | Придумай другой — он должен быть уникальным на всё приложение. |
| Красное «Нет прав на запись» | `schema.sql` выполнен не целиком: в конце файла включается защита RLS и политики. Выполни файл заново полностью. |
| «В базе нет функций для чатов» | Не выполнен `supabase/stage2.sql` — вернись к шагу 6. |
| «В базе старые правила доступа» | То же самое: выполни `supabase/stage2.sql`. |
| Сообщение приходит только после обновления страницы | В `stage2.sql` включается рассылка Realtime. Проверь в Supabase → **Database** → **Publications** → `supabase_realtime`: там должны быть отмечены `messages` и `chat_members`. |
| Уведомления не приходят | Проверь три вещи: нажата ли кнопка «Включить уведомления», разрешил ли браузер (замочек рядом с адресом), и открыт ли сайт хотя бы в фоновой вкладке. При закрытом сайте уведомлений не будет — это этап 5. |
| Заблокировал, а сообщения остались | Обнови страницу. Если не помогло — не выполнен `supabase/stage2b.sql` (шаг 6, пункт 4). |
| В поиске никого нет | Поиск ищет по @юзернейму и имени, минимум две буквы, и себя не показывает. Нужен второй зарегистрированный человек. |
